# Документація функцій та Протокол тестування

Цей документ містить опис усіх функцій у скрипті [export.py](file:///g:/ANTIGRAVITY/API%20BRAIN/export.py) та встановлює обов'язковий **Протокол забезпечення якості (QA)** для будь-яких майбутніх правок у проекті.

---

## 🏗️ Опис функцій (Каталог коду)

### 🔑 Авторизація та Керування сесіями (Async)
*   **`auth(client: httpx.AsyncClient, login: str, password: str) -> str`**
    *   *Призначення*: Авторизація в Brain API. Хешує пароль за алгоритмом MD5. Повертає Session ID (SID).
*   **`ensure_sid(client: httpx.AsyncClient) -> str`**
    *   *Призначення*: Повертає актуальний SID. Якщо в `_SID_STATE["sid"]` є збережений SID — повертає його, інакше викликає `auth()`.
*   **`reauth(client: httpx.AsyncClient) -> str`**
    *   *Призначення*: Примусовий перелогін у разі недійсної сесії. Має тротлінг (затримка не менше 15 секунд між авторизаціями) та ліміт спроб (`REAUTH_MAX_TOTAL = 5`). У разі перевищення ліміту викликає виключення `StopFetching`.
*   **`logout(client: httpx.AsyncClient, sid: str)`**
    *   *Призначення*: Закриття сесії на сервері Brain API.

### 📂 Робота з категоріями
*   **`fetch_categories(client: httpx.AsyncClient, sid: str, lang: str) -> list`** (Async)
    *   *Призначення*: Завантажує повне дерево категорій з Brain API. Має ретрай-цикл (до 4 спроб) з експоненційною затримкою.
*   **`load_categories_flat() -> list`** (Sync)
    *   *Призначення*: Зчитує категорії з локального файлу `categories.json`.
*   **`get_all_descendants(cats_by_parent: dict, parent_id: int) -> set`** (Sync)
    *   *Призначення*: Ітеративно (без рекурсії) збирає ID всіх дочірніх підкатегорій для вказаного `parent_id`.
*   **`save_categories_json(all_cats: list)`** (Sync)
    *   *Призначення*: Зберігає список категорій у файл `categories.json`.

### 📦 Завантаження товарів (Async)
*   **`fetch_products_page(client, sid, cat_id, lang, offset, limit=100) -> list`**
    *   *Призначення*: Завантажує одну сторінку товарів категорії. Ретраїть до 4 разів, автоматично обробляє випадок «мертвої сесії».
*   **`fetch_product_full(client, sid, pid) -> dict`**
    *   *Призначення*: Завантажує детальну картку товару (Фаза 2): описи, характеристики двома мовами (UA/RU). Ретраїть до 3 разів.
*   **`fetch_pictures(client, sid, pid) -> list`**
    *   *Призначення*: Завантажує посилання на зображення товару. Ретраїть до 3 разів.
*   **`fetch_all_products_full(client, sid, cat_ids, lang, out_cache, resume_from) -> list`**
    *   *Призначення*: Головний метод режиму **FULL**. Завантажує базові дані (Фаза 1), відсікає OOS/архівні товари, використовує `resume_from` для уникнення повторного збагачення карток, завантажує описи/фото в 4 потоки (Фаза 2), зберігає чекпоїнти.
*   **`fetch_prices_only(client, sid, cat_ids, lang) -> dict`**
    *   *Призначення*: Головний метод режиму **QUICK**. Завантажує сторінками всі товари з вибраних категорій і повертає словник їхніх базових параметрів (ціни, наявність, склади).
*   **`enrich_products(client, sid, todo) -> list`**
    *   *Призначення*: Виконує Фазу 2 (деталі/фото) для **нових** товарів, знайдених під час QUICK-оновлення.

### 💾 Робота з Кешем (Sync)
*   **`save_cache(products: list, path: Path, quiet: bool)`**
    *   *Призначення*: Записує дані в `products_cache.json`.
*   **`load_cache(path: Path) -> list`**
    *   *Призначення*: Зчитує товари з `products_cache.json`.
*   **`apply_prices_to_cache(products: list, prices: dict) -> list`**
    *   *Призначення*: Оновлює ціни та залишки товарів у кеші відповідно до свіжих даних QUICK-запиту. Товари, що зникли з API, маркує як архівні/OOS.

### ⚖️ Бізнес-логіка та Хелпери (Sync)
*   **`pid_of(p: dict) -> int | None`**
    *   *Призначення*: Безпечно повертає ID товару (перевіряє ключі `productID`, `id`, `product_id`).
*   **`is_enriched(p: dict) -> bool`**
    *   *Призначення*: Перевіряє, чи містить товар опис та зображення (чи пройдено Фазу 2).
*   **`safe(text) -> str`**
    *   *Призначення*: Видаляє керуючі символи з тексту.
*   **`is_true(v) -> bool`**
    *   *Призначення*: Нормалізує булеві значення Brain API (рядки, числа, булі).
*   **`base_price(p: dict) -> float`**
    *   *Призначення*: Визначає базову оптову гривневу ціну (`price_uah`) для нарахування націнки.
*   **`stock_qty(p: dict) -> int`**
    *   *Призначення*: Розраховує кількість залишків. Підсумовує `available` у разі OWN-режиму, інакше ставить заглушку `DEFAULT_STOCK = 2` за наявності складів у `stocks`.
*   **`vendor_name(p: dict) -> str`**
    *   *Призначення*: Визначає бренд товару з характеристик.
*   **`size_value(product: dict) -> tuple`**
    *   *Призначення*: Знаходить розмір для Kasta (зріст або розмір одягу/взуття).
*   **`build_group_id(product: dict) -> str`**
    *   *Призначення*: Генерує спільний ID для варіантів одного товару (за артикулом).
*   **`detect_gender(p: dict) -> str | None`**
    *   *Призначення*: Визначає стать (`girl`, `boy`, `woman`, `man` або `None`) для поділу підкатегорій дитячого одягу.
*   **`clean_html(text, limit) -> str`**
    *   *Призначення*: Видаляє HTML-теги та обрізає опис до 5000 символів (вимога Kasta).
*   **`strip_stopwords(text) -> str`**
    *   *Призначення*: Видаляє стоп-слова з назви товару для Kasta.

### 📝 Генерація XML фідів (Sync)
*   **`build_feed_xml(products, all_cats, feed, shop_url, output) -> dict`**
    *   *Призначення*: Створює стандартний XML-фід у форматі YML (Rozetka, Prom).
*   **`build_kasta_feed_xml(products, all_cats, feed, shop_url, output) -> dict`**
    *   *Призначення*: Створює фід під вимоги Kasta (з поділом категорій за статтю, group_id, розмірами).
*   **`compute_needed(all_selected: set, all_cats: list) -> set`**
    *   *Призначення*: Повертає повний набір категорій (включно з підкатегоріями) для побудови XML-дерева.
*   **`get_root_selected_categories(all_selected: set, all_cats: list) -> set`**
    *   *Призначення*: Повертає тільки батьківські вибрані категорії для уникнення дублювання при завантаженні.
*   **`build_all_feeds(products, all_cats, feeds, shop_url) -> list`**
    *   *Призначення*: Запускає білдери для кожного налаштованого фіда.
*   **`_export_link_block(results: list)`**
    *   *Призначення*: Виводить статистику згенерованих файлів.

### ⚙️ Стадії та Точка входу (Async)
*   **`stage_setup(client, base, feeds)`**
    *   *Призначення*: Отримує та зберігає категорії, передає сесію.
*   **`stage_shard(client, base, feeds)`**
    *   *Призначення*: Завантажує товари для окремого шарда.
*   **`stage_merge(base, feeds)`** (Sync)
    *   *Призначення*: Збирає кеші всіх шардів в один та генерує XML.
*   **`stage_solo(client, base, feeds, mode)`**
    *   *Призначення*: Запускає весь процес (FULL або QUICK) в один потік.
*   **`main()`**
    *   *Призначення*: Точка входу. Визначає стадію за змінною оточення `EXPORT_STAGE`.

## 🛡️ Протокол розробки та Тестування (QA Protocol)

Щоб запобігти ситуаціям, коли ШІ заявляє про успішне виконання, але код містить баги, встановлюється наступний обов'язковий протокол роботи для штучного інтелекту:

### 1. Етап планування
*   Перед початком роботи ШІ зобов'язаний створити або оновити [implementation_plan.md](file:///g:/ANTIGRAVITY/API%20BRAIN/implementation_plan.md) та дочекатися підтвердження від користувача.
*   Створити [task.md](file:///g:/ANTIGRAVITY/API%20BRAIN/task.md) для покрокового трекінгу виконання.

### 2. Етап розробки та локальних перевірок
*   **Ніякого коду "наосліп"**: Після будь-якої модифікації файлу `export.py` ШІ зобов'язаний викликати компілятор:
    ```powershell
    python -m py_compile export.py
    ```
    Якщо є хоча б одна синтаксична помилка, ШІ має негайно виправити її, не закриваючи крок.
*   **Локальний Dry Run (Сухий пуск)**: ШІ має запустити виконання скрипту локально:
    ```powershell
    python export.py
    ```
    Він має переконатися, що скрипт успішно зчитує `config.json` та `feeds.json`, ініціалізує логування та зупиняється виключно на етапі відсутності паролів (`Не задані BRAIN_LOGIN / BRAIN_PASSWORD`).

### 3. Етап тестування бізнес-логіки (Scratch Tests)
Якщо правки зачіпають бізнес-логіку (наприклад, стать `detect_gender`, націнки, залишки `stock_qty` чи групування `build_group_id`):
*   ШІ **зобов'язаний** створити тимчасовий тестовий скрипт у папці `scratch/` (наприклад, `scratch/test_logic.py`).
*   Скрипт повинен імпортувати змінену функцію з `export.py` та протестувати її на наборі тестових словників (mock data).
*   *Приклад тесту:*
    ```python
    import sys
    sys.path.append("..")
    from export import detect_gender
    # Перевірка дитячої статі
    test_prod = {"options": [{"OptionName": "Стать дитини", "ValueName": "Дівчинка"}]}
    assert detect_gender(test_prod) == "girl", "Помилка тесту статі дівчинки!"
    print("Тести логіки успішно пройдено!")
    ```
*   ШІ повинен запустити цей тестовий скрипт і додати вивід успішного проходження у своє повідомлення.

### 4. Фіксація змін (Ченджлог та Звіт)
*   **Mandatory Ledger**: Записати зміни в [AI_CHANGELOG.md](file:///g:/ANTIGRAVITY/API%20BRAIN/AI_CHANGELOG.md) у форматі: `[Date] - [Context] -> [Changes] -> [Impact]`.
*   **Користувацький Walkthrough**: Створити або оновити [walkthrough.md](file:///g:/ANTIGRAVITY/API%20BRAIN/walkthrough.md), де чітко розписати:
    1. Що конкретно змінилося.
    2. Як саме ШІ це протестував (надати результати запуску тестів із кроку 3).
    3. Інструкцію для користувача, як перевірити зміни на стейджингу або запустити фіди.
