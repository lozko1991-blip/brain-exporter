# 🧠 Brain API → XML Exporter (v5, sharded)

Автоматична вигрузка каталогу **Brain.com.ua** у XML-фіди для маркетплейсів
(**KASTA**, Rozetka / Prom). Працює **повністю на GitHub Actions** — без свого
сервера. Розрахований на великий каталог (**до ~40 000 товарів**) і витримує
збої/таймаути Brain без втрати даних.

---

## 📁 Структура проєкту

| Файл | Призначення |
|------|-------------|
| `export.py` | Ядро: качає Brain API, будує XML. Має стадії `setup / shard / merge / solo`. |
| `export.yml` | GitHub-workflow. **На GitHub має лежати в `.github/workflows/export.yml`** |
| `feeds.json` | Конфіг фідів (категорії, націнки, формат, поділ за статтю, префікси) |
| `index.html` | Адмінка (GitHub Pages) — візуальний вибір категорій → генерує `feeds.json` |
| `categories.json` | Дерево категорій Brain. Створюється/оновлюється **автоматично** |
| `KASTA_XML_правила.md` | Довідник вимог фіда KASTA (розміри, стоп-слова, ліміти, коди помилок) |
| `products_cache.json` | Кеш товарів. **Не в git** — живе в GitHub Release (може бути великим) |

> ⚙️ `config.json` — застарілий формат однієї вигрузки. Лишається лише як
> fallback, якщо `feeds.json` немає. Нове налаштування — через `feeds.json`.

---

## 🏗️ Як це працює (архітектура)

Один прогін Workflow розкладається на стадії:

```
prepare ──► setup ──► shard 0 ┐
                      shard 1 ├─(паралельно)─► merge ──► GitHub Release
                      shard 2 │
                      shard 3 ┘
```

- **prepare** — визначає режим (full/quick), мову, к-сть shard-ів.
- **setup** — логіниться в Brain **один раз**, зберігає `categories.json`,
  передає спільний `SID` усім shard-ам (у логах замаскований).
- **shard N** — кожен качає **свою частину** категорій (round-robin) на окремому
  runner-і. Так 40k товарів завантажуються за ~1.5 год замість ~5.5.
- **merge** — збирає всі частини в **ОДИН** `kasta.xml`, кладе його і кеш у
  **GitHub Release** (тег `feed`). Запускається завжди (`if: always()`), навіть
  якщо якийсь shard впав.

**Режими:**
- **FULL** — повна вигрузка (товари + описи + фото + характеристики). 3×/місяць.
- **QUICK** — лише ціни й наявність з кешу (швидко, одна джоба). 3×/день.

## 🚀 Налаштування (один раз)

### 1. Репозиторій
Залий усі файли в GitHub-репозиторій (напр. `brain-exporter`).
**Важливо:** `export.yml` має лежати саме як `.github/workflows/export.yml`.

### 2. Секрети Brain
**Settings → Secrets and variables → Actions → New repository secret:**

| Name | Value |
|------|-------|
| `BRAIN_LOGIN` | email на opt.brain.com.ua |
| `BRAIN_PASSWORD` | пароль (хешується MD5 у коді) |

> 🔒 Логін/пароль ніколи не потрапляють у код, логи чи чат — лише через Secrets.

### 3. GitHub Pages (для адмінки)
**Settings → Pages → Deploy from a branch → main / (root)**.
Адмінка: `https://ВАШ_АКАУНТ.github.io/brain-exporter/`

### 4. Налаштувати фіди в адмінці
1. Відкрий адмінку (Pages).
2. Признач **Формат** = KASTA (або Rozetka/Prom YML).
3. Постав галочки на потрібних категоріях.
4. (KASTA) для дитячих категорій постав галочку **поділу за статтю**.
5. Задай **націнку** (% + грн) і за потреби **префікси ID**.
6. Скопіюй згенерований `feeds.json` → встав у файл `feeds.json` у репо → Commit.

> Можна мати **кілька фідів** одночасно (вкладки «+ Додати фід»). Кожен має свій
> `id` → свій файл `output/{id}.xml` і своє посилання в Release.

## ▶️ Запуск

### Автоматично (за розкладом)
- **QUICK** — щодня о ~09:00 / 15:00 / 21:00 (Київ): оновлює ціни й наявність.
- **FULL** — 1, 11, 21 числа ~04:00 (Київ): повна перевигрузка.

### Вручну
**Actions → 🧠 Brain → XML Export → Run workflow**, параметри:
- `mode`: `full` або `quick`
- `lang`: `ua` / `ru` — впливає лише на **дерево категорій**
  (текст товару в KASTA **завжди двомовний**: `name_ua`+`name_ru`, опис теж).
- `shards`: кількість паралельних джоб (1 / 2 / 4 / 6).

### ⚠️ Перший запуск — обережно
Brain **офіційно не документує** ні rate-ліміт, ні чи дозволені паралельні сесії.
Тому **перший FULL запусти вручну з `shards=2`** і подивись логи. Якщо все чисто —
підіймай до 4. Якщо в логах сиплеться `♻️ SID відхилено` / `🛑 забагато
перелогінів` — Brain тримає лише одну сесію, став `shards=1` (працюватиме
послідовно, повільніше, але без ризику блокування).

## 🔗 Постійне посилання на фід (для KASTA)

Фіди віддаються через **GitHub Release** (тег `feed`) — один файл до **2 ГБ**.
Посилання **не змінюється**:

```
https://github.com/ВАШ_АКАУНТ/brain-exporter/releases/download/feed/kasta.xml
```

(де `kasta` — це `id` фіда з `feeds.json`).

Встав це посилання в кабінет KASTA (Rozetka/Prom — аналогічно своїм `id`.xml).

> Чому Release, а не `raw.githubusercontent`? `git push` відхиляє файли **>100 МБ**,
> а каталог на 40k товарів — це 200–500 МБ. Release тримає до 2 ГБ і не роздуває
> git-історію щоденними комітами кешу.

## 🛡️ Стійкість до збоїв Brain (як ми НЕ падаємо)

| Ризик | Захист |
|------|--------|
| Brain бачить 4 логіни як «атаку» | Один `auth` у `setup`, спільний SID на всі shard-и |
| SID прив'язаний до IP / відхилено | Автоперелогін у кожній fetch-функції |
| Каскад перелогінів (single-session Brain) | Тротлінг: не частіше 1×/30с, максимум 12 → потім коректна зупинка |
| Зависання/таймаут запиту | Жорсткий timeout + експоненційні повтори |
| Джоб уб'ють по таймауту (6 год) | `TIME_BUDGET_MIN=300`: зупиняємось і зберігаємо самі раніше |
| Збій посеред вигрузки | Чекпойнт кешу кожні 250 товарів + **resume** (не качаємо вже зроблене) |
| Один shard впав | `merge` (`if: always()`) бере що є; незмінені зрізи — з попереднього Release |
| Помилка одного товару | `return_exceptions=True` — товар пропускається, прогін триває |

**Підсумок:** у найгіршому разі фід просто оновиться частково (решта — останні
відомі дані), а наступний прогін докачає. Workflow **не падає**.

## 🧩 Логіка фіда KASTA (коротко)

- **Двомовність:** завжди `name_ua`+`name_ru`, `description_ua`+`description_ru`
  (HTML вирізається, ≤5000 символів).
- **Поділ за статтю** (опційно, лише для позначених категорій): дитячі товари
  за «Стать дитини» → підкатегорії `…g` (дівчинка) / `…b` (хлопчик); дорослі за
  «Стать» → `…w` / `…m`. Якщо ознаки немає — товар лишається в рідній категорії.
- **Розмір:** якщо явного «Розмір» немає (дитячий одяг має «Зріст», взуття —
  «Розмір взуття») — підставляємо `<param name="Розмір">` із цього джерела, щоб
  KASTA не відхилила за `SIZE_NOT_PROVIDED`.
- **Групування варіантів:** різні розміри/зрости однієї моделі зводяться в одну
  картку через `group_id` (за артикулом без розмірного суфікса).
- **`old_price`** додається лише якщо рекомендована ціна **строго більша** за `price`.
- **Префікси** `prefix_offer` / `prefix_category` (типово `br`) — щоб ID не
  конфліктували з іншими постачальниками на маркетплейсі.

Повний перелік вимог — у `KASTA_XML_правила.md`.

## 🧮 Ліміти й бюджет

- **KASTA:** до 1 ГБ / 200 000 товарів на файл, timeout завантаження 45 хв — з
  запасом.
- **GitHub job:** жорсткий ліміт 6 год. 4 shard-и × ~1.5 год для 40k — вкладається.
- **Actions-хвилини (приватний репо):** 2000/міс безкоштовно. QUICK 3×/день +
  FULL 3×/міс ≈ впритул. Якщо репо **публічний** — Actions безлімітні.

## ❓ Часті питання / усунення проблем

**У логах `🛑 забагато перелогінів` — що це?**
Brain не тримає кілька/довгих сесій. Постав `shards=1`, або попроси в Brain
статус OWN-режиму (тоді API віддає й точні залишки).

**Quick щоразу робить повну вигрузку.**
Не знайдено кеш у Release. Спершу має успішно відпрацювати хоч один FULL
(він кладе `products_cache.json` у Release).

**KASTA: `SIZE_NOT_PROVIDED` / `SIZE_NOT_FOUND`.**
Перевір, що в товара є «Зріст»/«Розмір»/«Розмір взуття» в Brain — інакше розмір
підставити нема звідки.

**Адмінка показує демо-категорії.**
`categories.json` ще не згенеровано — запусти Workflow (стадія setup створить його).

**Як підключитись до API Brain?**
support_b2b@brain.ua, реєстрація на opt.brain.com.ua зі статусом Адміністратор.
