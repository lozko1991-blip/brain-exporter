# Brain API Exporter Architecture

This document describes the technical architecture of the Brain API Exporter project. It is intended to help AI assistants understand the ecosystem and avoid introducing breaking changes.

## 🏗️ System Overview
- **Frontend (`index.html`)**: A standalone HTML file hosted on GitHub Pages. It loads categories from `categories.json` (generated by the backend) and allows the user to select categories for export.
- **Backend (`export.py`)**: A Python script executed automatically by GitHub Actions. It reads `feeds.json`, fetches product data from the Brain API, and generates XML feeds for marketplaces (Prom, Rozetka, Kasta).

## 🔄 The Data Cycle
1. **User Edit**: The user opens the frontend and modifies feed settings (markup, categories).
2. **Save to GitHub**: The frontend uses a GitHub Personal Access Token (PAT) stored in `localStorage` to make a `PUT` request to the GitHub REST API, updating `feeds.json` directly in the repository.
3. **Trigger Workflow**: The user clicks "Update" on the frontend, which sends a `POST` request to trigger the `export.yml` workflow via GitHub Actions `workflow_dispatch`.
4. **Execution**: GitHub Actions runs `export.py`.
5. **Output**: `export.py` creates `output/*.xml` files. The workflow then uploads these XMLs to the GitHub Releases page (tag `feed`) to bypass Git repository size limits.

## 🖥️ UI State Machine (index.html)
The frontend operates in 3 distinct states. You must preserve the logical separation of these states when modifying the UI:
1. **Loading State**: The `categories.json` file is being fetched from the server. Tree view shows a loading spinner.
2. **Manual Mode (No Token)**: `localStorage.getItem('gh_token')` is empty. The user sees a "Copy to Clipboard" button for their feeds configuration and must commit manually.
3. **Automated Mode (Token Present)**: `localStorage.getItem('gh_token')` exists. The UI reveals buttons to directly "Save to GitHub" and "Trigger Actions" using the REST API.

## 🤝 Component Data Contract (CRITICAL)
`feeds.json` is the bridge between the frontend and backend.
**RULE:** If you add or modify a field in `feeds.json`, you **MUST** update both `index.html` (the writer) and `export.py` (the reader) simultaneously.

### `feeds.json` (Configuration Schema)
```json
{
  "shop_url": "https://avi.com.ua",
  "feeds": [
    {
      "id": "rozetka",
      "name": "Rozetka",
      "format": "yml", // Or "kasta"
      "lang": "ua",
      "markup_percent": 15,
      "markup_fixed": 100,
      "prefix_offer": "br",
      "prefix_category": "br",
      "category_ids": [123, 456],
      "split_category_ids": [456] // Only for Kasta format to split by gender
    }
  ]
}
```

## ⚠️ Brain API Quirks & Handling
- **Session Management**: Brain API requires a `SID` (Session ID). The script uses a global `_SID_STATE` to prevent multiple overlapping auth requests.
- **Intermittent Failures**: The API sometimes returns `status: 0` for valid endpoints under load. `export.py` implements exponential backoff and retries (3 attempts). **Do not remove this.**
- **Concurrency**: Avoid running multiple instances of `export.py` simultaneously to prevent SID invalidation.

## ☁️ GitHub Actions Environment Constraints
- The `export.py` script runs on a clean Ubuntu runner in GitHub Actions.
- **Dependencies**: The script relies on built-in libraries (like `xml.etree.ElementTree`) and `requests`. 
- **RULE**: If you need to use a new third-party Python library (e.g., `pandas`, `lxml`), you MUST add a `pip install <library>` step in `.github/workflows/export.yml`. Otherwise, the script will crash in production.

## 🔑 Security & Secrets
The following GitHub Secrets are required for the Actions to run:
- `BRAIN_LOGIN`
- `BRAIN_PASSWORD`
- `GH_PAT` (for pushing to Releases)

**Security Rules:**
- Never hardcode these secrets into Python or JS files.
- If you add a new third-party integration, instruct the user to add the key to GitHub Secrets and access it via `os.environ.get()`.
- Never expose API tokens or PATs in `print()` or `console.log()`.
